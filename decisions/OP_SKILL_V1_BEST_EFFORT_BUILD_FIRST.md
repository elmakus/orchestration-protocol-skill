# OP Skill v1 — best-effort build first, final-candidate tests later

Decision revision: 1
Date: 2026-10-04
Status: accepted owner direction for material Strategic Planning re-entry
Authority role: delivery order and development-risk acceptance; not a production qualification verdict or a change to Definition R8 product/security semantics.

## Owner direction

Build the complete skill candidate on a best-effort basis using reasonable implementation assumptions. Native/behavioral qualification and corrections based on those observations belong to a separate procedure on the completed candidate, not an early prerequisite for authoring the rest of the skill.

The owner accepts that investment in a complete implementation may precede discovery of Android installation, helper, provider-tool or context limitations. The current lack of a native guarded test realization must not require the owner to provision Android testing before implementation planning/building can proceed.

## Scope of this decision

- Preserve the accepted native ChatGPT Android, portable skills-only target and eight profile outcomes from Definition R8.
- Preserve the accepted caller/OP boundary, effect caps, evidence-vs-authority distinction, safe recovery, procedural independence and no-external-backend product boundary.
- Replace P1's early live M01 prerequisite to broad construction with a build-first strategy. Record unsupported/unobserved host/package/tool assumptions explicitly; do not invent verified compatibility.
- During construction use proportionate basic non-inference checks for file/package coherence and helper correctness. Do not require the exhaustive behavioral/native qualification programme to precede completion of the implementation candidate.
- Deliver a complete, explicitly unqualified candidate plus separate final-candidate test instructions/procedure. Run those tests and make evidence-driven corrections later under their own authorized test obligation.
- Candidate completion is not a claim of Android compatibility, Q0-Q10 PASS, production admissibility or production release readiness. Definition R8's qualification/verdict rules still govern any such claim or production use.
- This direction authorizes no live probe, real-inference test, credential handling, account/settings change, consumer mutation or weakening/bypass of the environment's test policy. The missing native realization remains a later test prerequisite, not an implementation-investment gate.
